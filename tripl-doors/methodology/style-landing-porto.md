# Инструкция по стилям для генерации посадочных страниц

Этот файл — свод обязательных правил по оформлению для агента, который генерирует
посадочные страницы категорий для сайта завода «Сталь-Плюс»
(WooCommerce + тема **Porto**, конструктор **Elementor**, плагин попапов **Popup Maker**).

Правила составлены по итогам ручной доработки страницы «Двери для дома».
Их нужно применять ко **всем** новым посадочным страницам.

---

## Структура: каждая страница = два HTML-файла

Каждая посадочная категория оформляется как **два отдельных HTML-файла**. Они
вставляются в разные HTML-виджеты Elementor — до и после каталога WooCommerce:

1. **Верхний блок** — только блок на синем фоне (hero): заголовок, цифры,
   CTA-кнопка и фото категории. Это то, что идёт **от хлебных крошек до каталога
   WooCommerce**. Шапку сайта, меню и сами хлебные крошки в файл **не** включать —
   они уже есть на странице.

2. **Нижний блок** — весь контент **после каталога WooCommerce и до подвала**:
   текст, таблицы, схемы, FAQ, контакты и т.д. Сам подвал (footer) в файл **не**
   включать — он часть темы сайта.

Между этими двумя блоками WooCommerce сам выводит сетку товаров (каталог) — её
верстать и включать в файлы не нужно.

## 1. Действие на CTA-кнопках (попап «Связаться с нами»)

**Правило.** Все кнопки призыва к действию (Call to Action) — «Вызвать замерщика»,
«Проконсультироваться», «Оставить заявку», «Рассчитать стоимость» и любые
аналогичные — должны открывать один и тот же попап **«Связаться с нами»**
(WhatsApp / Telegram / Max / Позвонить).

**Как это работает.** На сайте установлен плагин **Popup Maker**. Нужный попап
(внутренний id `pum-9515`) настроен на срабатывание по клику на **любую ссылку
с `href="#svyaz"`** — это его штатный триггер (`click_open`, селектор
`a[href="#svyaz"]`). Обработчик делегированный, поэтому работает и для элементов,
добавленных в готовый HTML-блок. Плагин сам вызывает `preventDefault()`, так что
переход по якорю и «прыжок» страницы не происходят.

**Как делать.** CTA-кнопку оформлять как ссылку `<a>` с `href="#svyaz"`:

```html
<a class="cta" href="#svyaz">Вызвать замерщика</a>
```

**Чего НЕ делать.**
- Не привязывать действие к классу `.my-fixed-element` — этот класс у сайтовой
  кнопки отвечает только за её фиксированное положение (плавающая кнопка справа
  внизу) и **не** открывает попап. Проверено: сам по себе класс не срабатывает.
- Не вешать на кнопку собственный `onclick`/`PUM.open(...)` — используем штатный
  триггер `href="#svyaz"`, он надёжнее и не зависит от порядка загрузки скриптов.

> Попап подключён на всём сайте, поэтому дополнительная настройка на конкретной
> странице не требуется — достаточно `href="#svyaz"`.

## 2. Ховер для тёмных CTA-кнопок

**Правило.** Если у CTA-кнопки **тёмный фон** (базовый тёмный `#22252a`), то при
наведении фон должен **плавно за 0,15 секунды** меняться на **синий `#0077b3`**,
текст при этом остаётся белым. Это повторяет поведение кнопки «В корзину» на
страницах товаров (стандартная кнопка WooCommerce в теме Porto: обычное состояние —
тёмная, ховер — синяя).

**Как делать.** К классу кнопки добавить `transition`, и правило `:hover`:

```css
/* Базовое состояние тёмной кнопки */
.cta{
  background:#22252a;   /* тёмный фон */
  color:#fff;
  border:0;
  transition:color .15s, background-color .15s, border-color .15s, box-shadow .15s, transform .2s;
}
/* Ховер как у кнопки «В корзину» (тема Porto): тёмный → синий */
.cta:hover{
  background:#0077b3;
  color:#fff;
  text-decoration:none;
}
```

Строку `transition` брать ровно такой, как выше, — это тот же набор переходов, что
у сайтовой кнопки.

## 3. Растягивание фона блока на всю ширину экрана (full-bleed)

**Правило.** Блоки, у которых фон должен занимать **всю ширину окна** (например,
верхний синий hero-блок), при вставке в узкий контейнер контента WordPress
«вписываются» в ширину контента и смотрятся неправильно. Такие блоки нужно сразу
дополнять кодом full-bleed.

**Как делать.** На саму секцию (не на внутренний контейнер) добавить отрицательные
боковые отступы:

```css
.hero{
  background:#102d50;                    /* фон на всю ширину */
  margin-left:calc(50% - 50vw);
  margin-right:calc(50% - 50vw);
}
```

Внутренний контейнер контента при этом оставляем центрированным и ограниченным по
ширине, чтобы текст не растягивался на весь экран:

```css
.wrap{ max-width:1160px; margin:0 auto; padding:0 16px; }
```

**Почему так, а не `width:100vw`.** Приём `calc(50% - 50vw)` не создаёт лишней
горизонтальной прокрутки из-за ширины полосы скролла, в отличие от `100vw`.

**Фон секций в тексте (белые и серые полосы).** Внутри контентных блоков секции
чередуются: основной текст — на белом фоне, часть секций — на сером (`#f4f4f4`),
и серый фон должен тянуться **на всю ширину экрана**. Два важных момента:

1. Белый фон белым секциям задавать **явно** (`background:#fff`). Иначе тема Porto
   красит любой элемент с классом `.section` в серый, и «белые» секции становятся
   серыми.
2. Серым секциям добавлять тот же full-bleed, что и hero (`margin-left/right:
   calc(50% - 50vw)`), а контент оставлять по центру во внутреннем `.wrap`.

```css
.section{ padding:64px 0; background:#fff; }                 /* белые — фон явно */
.section--muted{                                            /* серые — во всю ширину */
  background:#f4f4f4;
  margin-left:calc(50% - 50vw);
  margin-right:calc(50% - 50vw);
}
.wrap{ max-width:1160px; margin:0 auto; padding:0 16px; }   /* контент по центру */
```

## 4. Фото категории в hero-блок

В правой части hero вместо картинки ставим серверный шорткод `[cat_hero_image]` —
он сам подставляет фото текущей категории WooCommerce (URL вручную прописывать не
нужно; шорткод уже подключён на сайте):

```html
<div class="photo">[cat_hero_image]</div>
```

Если у категории фото не задано — остаётся синий фон-градиент (заглушка `.photo`).

Фото всегда выводим горизонтальным прямоугольником (4:3) — иначе вертикальный
снимок растянет блок по высоте. Задаём контейнеру фиксированное соотношение сторон,
а фото обрезаем по центру:

```css
.photo{ aspect-ratio:4 / 3; overflow:hidden; }
.photo img{ width:100%; height:100%; object-fit:cover; object-position:center; }
```

## 5. Общие правила (чтобы не конфликтовать с темой)

- **Изолировать стили блока.** Тема Porto использует распространённые имена классов
  (`.section`, `.wrap`, `.card`, `.grid`, `.cta`, `.btn` и т.п.). Чтобы стили блока
  не «поплыли» и не задели тему, оборачивать каждый блок в контейнер с уникальным
  классом-префиксом и ограничивать все селекторы этим классом. Пример:
  `.szp-hero { ... }`, `.szp-hero .wrap { ... }` для верхнего блока и
  `.szp-content { ... }`, `.szp-content .wrap { ... }` для нижнего.
- **Каталог не верстать.** Между верхним и нижним блоком выводится сетка товаров
  WooCommerce — она генерируется движком автоматически, в HTML-блоки её включать
  не нужно.
- **Шрифт.** Наборный (основной) шрифт страниц — **Poppins Regular** (вес 400),
  как на сайте (тема Porto грузит его сама). Использовать его во всех блоках:

  ```css
  font-family:"Poppins", sans-serif;
  font-weight:400;
  ```

  Свои `<link>`/`@import` на другой шрифт (например, PT Sans) в блоки не добавлять —
  чтобы вёрстка совпадала с остальным сайтом.

### Палитра сайта (для единообразия)

| Назначение | Цвет |
|---|---|
| Тёмно-синий (фон hero, тёмный текст) | `#102d50` / `#22252a` |
| Синий (акцент, primary) | `#0088cd` (у темы Porto — `#0088cc`) |
| Синий для ховера кнопок | `#0077b3` |
| Белый | `#ffffff` |
| Фон-подложка секций | `#f4f4f4` |
| Границы | `#e7e7e7` |
| Приглушённый серый текст | `#828b91` |

## 6. Дата обновления в нижнем блоке

Строку «Дата обновления» не писать вручную. Формат — **месяц и год** (без числа),
значение = **текущий месяц минус 2**. Пример: сейчас сентябрь 2026 → «июль 2026 года».
Дату подставляет скрипт:

```html
Дата обновления: <span id="szp-update-date">июль 2026 года</span>.

<script>
(function(){
  var el = document.getElementById('szp-update-date');
  if(!el) return;
  var months = ["январь","февраль","март","апрель","май","июнь",
                "июль","август","сентябрь","октябрь","ноябрь","декабрь"];
  var d = new Date();
  d.setDate(1);
  d.setMonth(d.getMonth() - 2);
  el.textContent = months[d.getMonth()] + " " + d.getFullYear() + " года";
})();
</script>
```
