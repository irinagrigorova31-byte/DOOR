# Кокон-карта (семантические силосы) + граф внутренних ссылок ON-SITE

Проектная карта внутренней перелинковки. **Ведёт `tz-writer`** (проекция на страницу — блок
ПЕРЕЛИНКОВКА каждого ТЗ). **Целостность проверяет `cluster-inspector`** (§5, против этой карты).
**Разводит `page-builder`** (из блоков ПЕРЕЛИНКОВКА, выведенных отсюда). Это не текст страницы — это
граф; заполняется по ходу проектирования ТЗ, при параллели дописывается (чужие коконы не перезаписывать).

## Что такое кокон
Кокон — тематический кластер страниц вокруг одной темы: **опорная (pillar)** держит общую теорию,
**дочерние** несут только меняющееся (цифры, ограничения, локальную специфику). Внутри кокона: дети
ссылаются на pillar, pillar — на детей, дети — на соседей по смыслу (sibling). Между коконами —
только явные **мосты** (по одной осмысленной связи), а не сплошная линковка всех со всеми.

## Правила
- **Один анкор = одна цель.** Разные анкоры на один URL — проверить, что это канонические имена, а
  не коммерческие ключи. Один анкор на разные URL — конфликт (cluster-inspector завернёт).
- Анкор = **каноническое имя сущности** из `data/entities.md`, не «купить X дёшево».
- Нет изолированных страниц: у каждой ≥1 входящая ссылка внутри кокона.
- Мост между коконами заявляется здесь явно; самодеятельный мост в тексте, которого нет в карте, —
  расхождение.

## Коконы

> **Проект однокластерный (кластер 01 → одна витрина).** Кокон из ОДНОЙ опорной страницы: серии
> дочерних SEO-страниц нет, фасетки (терморазрыв / в квартиру / в дом / с зеркалом / по размеру /
> противопожарные) — это **фильтры-теги ВНУТРИ витрины**, отдельных URL не имеют (`about.md`, охват).
> Заполнено tz-writer из `data/tz/tz-01.md` (2026-09-18). Мосты — только на СУЩЕСТВУЮЩИЕ разделы сайта,
> новые страницы не создаём.

### Кокон 1: Входные двери (Липецк) — pillar `/product-category/vhodnye-dveri/`
| Страница (URL) | Роль | Ссылки СЮДА (откуда · анкор) | Ссылки ОТСЮДА (куда · анкор) |
|---|---|---|---|
| `/product-category/vhodnye-dveri/` | **pillar** (единственный узел кластера 01) | Главная `/` · «Входные двери»; меню «Каталог продукции» · «Входные двери»; хлебные крошки Каталог → · «Входные двери» | см. мосты ниже |

Дочерних SEO-страниц в коконе нет. Изолированной страница не является (≥3 входящих: главная, меню, крошки).

### Мосты между коконами / на существующие разделы сайта
| Из · страница | В · раздел (существующий) | Анкор (каноническое имя) | Зачем мост (одна строка) |
|---|---|---|---|
| Кокон 1 · витрина «Входные двери» | категория «Противопожарные двери» | «противопожарные двери» | из H2 «Противопожарные и технические двери» — смежный продукт завода (условная формулировка) |
| Кокон 1 · витрина «Входные двери» | `/o-nas/` «О заводе» | «завод «Сталь-Плюс»» | из блока «Почему завод» — доказательство производства. ⚠️ ставить ПОСЛЕ починки Lorem ipsum (external-tasks E-8) |
| Кокон 1 · витрина «Входные двери» | `/contact/` «Контакты» | «завод в Липецке» | из блока «Контакты/как приехать» — NAP, как доехать до цеха |

**Правило анкоров соблюдено:** один анкор = одна цель; анкоры — канонические имена сущностей
(`entities.md`), не коммерческие ключи. Конфликта III-7 нет (серии нет). Проверяет cluster-inspector.
