> Правило 4: каждое значение разметки есть в видимом тексте `drafts/page-01.md` (добавлен видимый блок «Контакты» под NAP).

## JSON-LD — что вошло (8 узлов @graph, JSON валиден)
- `LocalBusiness` — NAP (398056, ул. Им. Баумана стр. 307Е оф. 1, тел., email), taxID/ОГРН/ИНН,
  `areaServed` Липецк, `sameAs` (Я.Карты, 2ГИС, VK, TG, Avito, РБК — тождественные профили компании),
  `hasCertification` = противопожарные ДПМ EI60/S15 (№ ЕАЭС RU C-RU.НЕ25.В.00065/25, до 2030-03-20).
- `CollectionPage` — витрина, `dateModified` 2026-09-20, `citation` на ГОСТ 31173-2016 и ГОСТ Р 57327-2016 (первоисточники).
- `BreadcrumbList` — Главная → Каталог → Входные двери.
- `Service` ×4 — замер · доставка · монтаж · изготовление по индивидуальным размерам (от 2 суток), provider = org, areaServed Липецк.
- `FAQPage` — 2 вопроса (дешёвая дверь; индивидуальные размеры) дословно из текста.

## Что НЕ вошло и почему (честные пробелы)
- **`ItemList`/`Product`/`Offer` (товары с ценами)** — НЕ фабрикуем. Цены и модели берутся из ЖИВЫХ карточек
  WooCommerce; их машиночитаемый `Product`/`Offer` генерирует page-builder/движок из реального каталога.
  Это и есть пустота №5 (машиночитаемый прайс — ниша под цитируемость), но только на реальных данных.
- **FAQ №3 «гарантия при чужом монтаже»** — ответ `[ТРЕБУЕТСЯ]`, в FAQPage НЕ включён (нельзя ставить заглушку в разметку).
- **`AggregateRating`** — НЕ ставим (2ГИС 5,0 при 2–3 отзывах — self-serving, тонкая база; cheatsheet §1/§3).
- **Wikidata `sameAs` бренда** — нет (записи о компании в Wikidata нет; не выдумывать).
- **ГОСТ 31173-2016 как `hasCertification` с номером** — номер ССГБ RU.СП01.Н00697 НЕ в видимом тексте,
  поэтому в разметке дан как `citation` (ссылка на стандарт), а не как Certification с номером (правило 4).

## Корректность свойств (cheatsheet)
- `warranty` НЕ вешали на Service; гарантия — текстом (числом не выпячиваем).
- `instrument` не использован. `sameAs` организации — только её профили (бренд-Q внутрь не пихали, его нет).
- «валидно ≠ правдиво ≠ сниппет покажут»: цель — машиночитаемость/извлекаемость, НЕ rich-сниппет как KPI.

## Инфографика (3 inline-SVG, `drafts/page-01-infographics.html`)
- **Рис. 1** — дерево решений «Нужен ли терморазрыв» (в H2 «Нужен ли терморазрыв»): улица/тамбур → нужен (зелёный);
  тёплый подъезд → переплата (красный). Несёт пустоту №4, чего нет в тексте таблицей.
- **Рис. 2** — разрез полотна «что внутри» (в H2 «Какая дверь надёжная»): слои сталь → рёбра → наполнитель
  («не гофрокартон») → отделка → уплотнение. Значения `[ТРЕБУЕТСЯ]` — структура готова, числа не выдуманы.
- **Рис. 3** — определитель «обычная ДМ vs противопожарная ДПМ» (в H2 «Противопожарные двери»): governance —
  визуально разводит продукты, EI60 только у ДПМ. Данные verified.
- Все: палитра бренда, PT Sans, квадратные углы, `role="img"` + `title`/`desc`, адаптив (viewBox + max-width:100%).
- НЕ дублируют HTML-таблицы витрины; логотипов конкурентов/рейтинга нет.
